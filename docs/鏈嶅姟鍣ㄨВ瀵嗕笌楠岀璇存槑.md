# 服务器解密与本地数据库加密说明

客户端上传到服务器的是一个外层 JSON，真正的数据在 `data` 字段里，使用 AES-GCM 加密：

```json
{
  "client_version": "1.0",
  "data": "base64(nonce + ciphertext + tag)"
}
```

## 解密规则

- 加密算法：AES-GCM
- Nonce：Base64 解码后前 12 字节
- 密文和认证 Tag：Base64 解码后第 13 字节到末尾
- associated_data：`None`
- 当前客户端 AES key：

```python
AES_KEY = b"mc_enhance_sync_secret_key_32b!!"
```

服务端解密示例：

```python
import base64
import json
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

AES_KEY = b"mc_enhance_sync_secret_key_32b!!"


def decrypt_upload(outer_payload: dict) -> dict:
    raw = base64.b64decode(outer_payload["data"])
    nonce = raw[:12]
    cipher_text = raw[12:]
    plaintext = AESGCM(AES_KEY).decrypt(nonce, cipher_text, None)
    return json.loads(plaintext.decode("utf-8"))
```

解密后的数据结构大致是：

```json
{
  "client_ip": "1.2.3.4",
  "client_ip_source": "myip.ipip.net",
  "client_ip_raw": "当前 IP：1.2.3.4 来自于...",
  "client_ip_fetched_at": 1777890000.0,
  "accounts": [],
  "echo_info": [],
  "echo_substats": []
}
```

## 本地数据库 SQLCipher

客户端主库 `mc_enhance.db` 放在用户数据目录，Windows 默认路径为 `%LOCALAPPDATA%\mc-enhance-helper\mc_enhance.db`，并默认尝试使用 SQLCipher。加密 key 由客户端首次启动时本机生成，并用 Windows DPAPI 保护后保存到同一个用户本地应用数据目录。这样普通 SQLite 工具不能直接打开主库，密钥文件也不是明文。

客户端需要安装 SQLCipher DBAPI 驱动，例如 `sqlcipher3` / `sqlcipher3-binary` / `pysqlcipher3` 其中之一。源码开发环境如果没有驱动，会打印提示并回退到普通 SQLite；打包后的客户端默认要求驱动存在，否则直接报错，避免发布版悄悄变成明文库。

如果已有明文 `mc_enhance.db`，客户端在 SQLCipher 驱动可用时会自动导出成加密库，并保留一个 `mc_enhance.db.plain.bak` 备份。

旧版本如果把数据库放在程序目录或当前工作目录，新版本首次启动时会在用户数据目录不存在主库的情况下复制一份过去，旧文件会保留不删除。

运行时 JSON 配置同样放在用户数据目录下的 `data` 子目录，例如 `%LOCALAPPDATA%\mc-enhance-helper\data\strategy_priority.json`。首次运行会从随包资源复制默认配置，已有用户配置不会被 exe 更新覆盖。

数据库里还会创建一个提醒表：

```text
你能看到这个说明你是懂技术的，不要污染数据哦
```

这个表不参与业务统计，只是给直接打开库的人看的提示。

## SQLCipher Python 安装环境

| 场景 | 推荐包 | 安装命令 | 说明 |
| --- | --- | --- | --- |
| Windows 开发/打包 | `sqlcipher3` | `uv pip install -r requirements-sqlcipher.txt` | 推荐方案，PyPI 提供 Windows wheel，适合当前 Python 3.11 环境。 |
| Windows 纯 pip | `sqlcipher3` | `python -m pip install "sqlcipher3>=0.6.2"` | 不使用 `uv` 时用这个。 |
| Linux wheel 环境 | `sqlcipher3-binary` | `python -m pip install sqlcipher3-binary` | manylinux wheel 更省事；是否适配以目标发行版为准。 |
| 已有系统 SQLCipher | `pysqlcipher3` | `python -m pip install pysqlcipher3` | 通常需要系统已安装 `libsqlcipher` 和编译环境，不推荐作为 Windows 发布首选。 |

当前根目录已有 [requirements-sqlcipher.txt](../requirements-sqlcipher.txt)：

```text
sqlcipher3>=0.6.2
```ha

当前打包脚本 [build_package.ps1](../build_package.ps1) 已在 `uv sync --extra dev` 后执行：

```powershell
uv pip install -r requirements-sqlcipher.txt
```

PyInstaller 也已经加入 SQLCipher hidden imports：

```powershell
--hidden-import sqlcipher3
--hidden-import sqlcipher3.dbapi2
--hidden-import pysqlcipher3.dbapi2
```

验证当前环境是否可用：

```powershell
uv run python -c "import sqlcipher3; print(sqlcipher3.sqlite_version)"
```

如果能打印版本号，客户端就能使用 SQLCipher 驱动。若源码开发时暂时不想安装 SQLCipher，可以设置：

```powershell
$env:MC_DB_USE_SQLCIPHER = "0"
```

## 入库策略

服务器解密后可以直接读取 `accounts`、`echo_info`、`echo_substats` 三组数据。客户端当前只读取服务端响应里的 `status`、`message`、`total_count`、`today_count`：

```json
{
  "status": "success",
  "message": "data received and saved",
  "total_count": 12345,
  "today_count": 678
}
```
