核心能力

把强化过程从“盯屏感觉”变成可追踪的数据流。

工具围绕声骸详情页和强化页建立 active context，减少页面切换造成的误刷新，并把识别结果整理成浮窗可读的强化建议。

Capture

窗口捕获

定位鸣潮客户端窗口，支持 WGC、DXGI、PrintWindow 等回退路径，为 OCR 和检测提供稳定帧。

Vision

面板识别

YOLO/ONNX 检测 echo_panel 与 enhance_panel，RapidOCR 读取中文面板文本并进行行列归并。

Parser

词条解析

标准化主词条、副词条和数值档位，兼容常见 OCR 错字，区分攻击、防御百分比与固定值。

Context

声骸会话跟踪

以详情页为锚点维护 ActiveEchoContext，强化页只延续当前声骸，连续不匹配才切换。

Advice

强化建议

结合已有辅音、剩余孔位、有效词条概率和等级成本，推荐继续、暂存、抽离或换胚。

Sync

样本同步

本地 SQLite 断点续传，服务器返回总样本和今日样本，浮窗同步展示大数据统计。

运行流程

从游戏窗口到强化决策，整条链路在一个浮窗里闭环。

01
锁定客户端 识别进程、窗口和 UID，绑定本机账号与客户端启动状态。
02
检测面板 基于场景匹配和模型检测提取声骸相关区域。
03
抽取观测 读取名称、套装、主词条、等级、COST 和辅音槽状态。
04
计算概率 根据历史样本和优先级推断剩余孔位有效率。
05
给出建议 把概率、成本和当前结果合并成用户能立即执行的动作。

轻量发布包

  • 开发阶段使用 yolov8_custom.pt、Torch 和 ultralytics。
  • 发布阶段导出 yolov8_custom.onnx，用 ONNX Runtime/DirectML 推理。
  • 打包时排除 torch、torchvision、torchaudio 和 ultralytics，避免 5GB 级运行库。

可更新配置

  • data/*.json 在开发环境直接读取仓库根目录。
  • 打包后首次运行会把默认配置复制到 exe 同级 data 目录。
  • 用户后续调整策略、词典和面板布局，只需要修改程序目录里的 JSON。
